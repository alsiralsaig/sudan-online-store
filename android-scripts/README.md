# بناء تطبيقات أندرويد (كاشير / متجر / إدارة)

ثلاثة تطبيقات أصلية من نفس الكود، لكل واحد معرّف واسم وأيقونة مستقلة:

| التطبيق | Package ID | يفتح |
|---|---|---|
| كاشير سند | `sd.sanad.merchant` | `/?app=merchant` |
| متجر سند | `sd.sanad.client` | `/?app=client` |
| إدارة سند | `sd.sanad.admin` | `/?app=super_admin` |

## البناء
```bash
npm ci
npm run native:setup     # JDK 21 + Android SDK API 35، مرة واحدة لكل بيئة
npm run native:build     # يبني الواجهة native-mode ثم يزامن Capacitor ويبني التطبيقات الثلاثة
```
النواتج في `apk-output/` داخل جذر المشروع.

إذا وُجدت مفاتيح التطبيقات الثلاثة في `/home/user/sanad-signing-keys/` يُبنى إصدار release موقّع. إذا لم توجد، يُبنى تلقائياً إصدار debug قابل للتثبيت للاختبار، لكنه **ليس إصدار متجر ولا يجوز نشره كتحديث للإصدارات الموقعة**. يمكن تحديد السلوك صراحةً عبر `SANAD_BUILD_TYPE=debug` أو `SANAD_BUILD_TYPE=release`؛ وضع release يتطلب مفاتيح التوقيع الأصلية.

## مفاتيح التوقيع والنشر
- التحديث إلى نفس التطبيق يجب أن يُوقّع بالمفتاح الأصلي نفسه، وإلا يرفض أندرويد تثبيته كتحديث.
- بصمات الشهادات المنشورة في `public/.well-known/assetlinks.json` مرتبطة بمفاتيح الإصدار المنشور.
- بناء APK لا يرفع الملفات إلى أي خدمة؛ النشر يحتاج خطوة منفصلة ومراجعة صريحة.
- `server.androidScheme=https` يجعل الواجهة تُقدَّم من `https://localhost`، لذلك يُبنى وضع native بعنوان API مطلق (`VITE_API_BASE`) وتُرسل الجلسة كـBearer.
